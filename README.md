# SPECIMEN

A collectible rare-plant game. **This repository is Phase 0: a clickable reveal prototype.**

Tap a sealed clay egg sitting in a terracotta pot. It cracks, then bursts, and a plant grows out of the pot, procedurally drawn, with a rarity you did not choose. A herbarium-style specimen tag names it. Then: **One more**.

Phase 0 exists to answer one question before anything else is built: *does the reveal feel good enough that people want another?* The exit test (from the [business plan](docs/business-plan/SPECIMEN_Full_Business_Plan.pdf), section 11.1) is **more than 60% of about 50 people want one more reveal**. Everything else in the plan waits for that answer. See [`docs/phase0-playtest.md`](docs/phase0-playtest.md) for how to run it and read the result, and [`HANDOFF.md`](HANDOFF.md) for the project context and decisions.

Scope is deliberately small: 3 plants, 1 pot, synthesised sound. No economy, no accounts, no social, no backend.

## Run it

Needs Node 22.18 or newer.

```bash
npm install
npm run dev        # http://localhost:5173  (also opens on your phone via the Network URL)
```

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server with hot reload |
| `npm run build` | Typecheck, then a static production build in `dist/` (about 95 KB, about 35 KB gzipped, no assets to host) |
| `npm run preview` | Serve the production build locally |
| `npm test` | Unit tests (Vitest, about 3 s) |
| `npm run e2e` | Browser checks in a real Chrome: touch and keyboard playthroughs, dialogs, reduced motion, audio render |
| `npm run shots -- grail monstera` | Deterministic screenshots of every moment of a reveal, into `e2e-out/` |
| `npm run playtest:report -- a.jsonl b.jsonl` | Turn exported playtest logs into the verdict |

`/gallery.html` shows every species in every form on one sheet (`?seed=123` re-rolls the variegation, `?species=pilea` focuses one). It is the quickest way to review the art.

The build is plain static files with relative paths, so it works from any host or sub-folder: GitHub Pages, itch.io, S3, a USB stick.

### Controls

- **Tap or click** the pot, three times. The first two crack it, the third breaks it.
- **Keyboard:** Tab to the pot, then Enter or Space. After the reveal, focus moves to **One more**.
- Tap the finished plant to make its leaves flutter.
- The speaker button mutes; the choice is remembered.
- **Odds & info** shows the published odds, how the game is made and what the test records.

### URL switches (development, QA and the facilitator)

| Switch | Effect |
| --- | --- |
| `?test=1` | Show the facilitator panel and expose `window.__specimen` for tests |
| `?force=grail` | Force the rarity (`common`, `uncommon`, `rare`, `grail`) |
| `?species=pilea` | Force the species (`monstera`, `snake`, `pilea`) |
| `?seed=42` | Make the roll sequence reproducible |
| `?manual=1` | No animation loop; a test drives time (used by `npm run shots`) |
| `?sound=0` | Start muted |
| `?motion=reduce` or `full` | Override the operating system's reduced-motion setting |

Any run with `force`, `species` or `seed` is recorded as a **debug run** and is **excluded from playtest results**, so a demo can never contaminate the numbers. Holding the SPECIMEN wordmark for a second, or pressing Shift+T, also opens the facilitator panel (phones have no Shift key).

## How it works

```
Reveal  ──cues──▶  Game  ──▶  Scene   (canvas: egg, cracks, shards, particles, plants)
(pure state        │    ──▶  Audio   (WebAudio synthesis)
 machine, real     │    ──▶  Ui      (DOM: tag, button, dialog)
 time)             └────▶  Playtest log (localStorage)
```

- **`src/reveal.ts`** is the director: a small state machine on real time with no canvas, DOM or audio in it. It decides *when* things happen and emits cues (`drop`, `crack`, `burst`, `sprout`, `fanfare`, `tag`, `settled`...). It is fully unit-tested, including the trust properties below.
- **The roll is requested when the pot drops, before any tap.** Every post-roll cue carries that same result object. The animation reveals an outcome; it never decides one. Phase 0 rolls on the device (`LocalRollSource`), which is fine for a feel test and **not tamper-proof**. The `RollSource` interface is the seam where Phase 2's server-signed rolls plug in without touching the game.
- **A plant is a pure function of `(species, form, seed)`.** Leaf outlines, slits, veins, gradients and variegation are generated by code (`src/plants/`), so the same roll result draws the same plant on every client, and 100+ species need no hand-drawn art. Sprites are built one leaf per frame while the pot sits idle, so nothing hitches during the reveal.
- **Two clocks.** The reveal runs on real time; the scene runs on a visual clock the game can freeze (a 100 ms hit-stop on the final tap) or slow (a brief slow-motion on Rare and Grail bursts) without bending the pacing or the trust properties.
- **Tuning lives in [`src/config.ts`](src/config.ts):** rarity names, odds, colours, timings, how much the cracks hint at the rarity before the burst (`TUNING.tell`), camera push, slow-motion. The odds table players read is generated from the same file, so it cannot drift from what the game does.
- **Sound** is synthesised in the browser (`src/audio.ts`); *what* plays for each rarity is plain data in `src/audio-score.ts` and is unit-tested. There are no audio files.

### Performance

Phones vary a lot, and a laggy reveal would fail the test for the wrong reason, so:

- The static pot and plinth are pre-rendered once and blitted; the shell is a sprite too.
- No `backdrop-filter`, no per-frame `shadowBlur`, no `ctx.filter`: all known frame-rate traps on weak GPUs.
- A frame-rate governor (`src/governor.ts`, unit-tested) lowers the canvas resolution step by step, never below 1 device pixel per CSS pixel, if the device sustains under about 25 fps. A 30 fps operating-system cap does not trigger it. Each drop is logged as `quality_drop`, and the report counts affected participants so you can discount their verdicts.

### Accessibility

The pot is a real `<button>`; the whole game plays by keyboard; reveals are announced through a `role="status"` region; rarity is shown by pips and a label as well as colour; `prefers-reduced-motion` calms the flash, shake, slow-motion and particle counts; touch targets are at least 44 px. The only bright flash is on the burst (a Grail's fanfare adds a much gentler one about a second later), well inside the three-flashes-per-second guideline.

## Art, sound and AI disclosure

Every plant is drawn by code and every sound is synthesised in the browser. **No generative-AI images or audio are used.** The code was written with AI assistance. The same statement is shown to players in **Odds & info**. The plan commits to disclosing AI use from day one; edit that text there if the facts change.

## Testing

- `npm test`: 120 unit tests covering the odds and roll fairness, the reveal state machine, layout across 20+ screen shapes, the frame-rate governor, the audio score, URL parsing, and all of the playtest statistics and logging.
- `npm run e2e`: starts its own dev server and drives a real headless Chrome. It needs Chrome or Chromium: set `CHROME_PATH` if it is not in a standard place. On a machine with no browser, `npm i --no-save @sparticuz/chromium` provides one, and `E2E_NO_SANDBOX=1` may be needed inside containers. `E2E_URL=http://localhost:4173 npm run e2e` tests an already-running server, for example `npm run preview`, and skips the two checks that import source modules.

## Known gaps

- **Not yet tested on real phones.** All browser testing so far ran in headless Chromium with software rendering, which is far slower and behaves differently from a phone GPU. Do a dry run on the devices you will test with, especially an older Android.
- **iOS and sound.** Browsers allow audio only after a touch, so on iOS the very first crack can be a beat late. The ringer switch may also mute web audio on older iOS versions; the build requests playback mode on newer ones. See the playtest guide.
- **No PWA yet** (manifest, icons, offline service worker): deferred until the concept passes.
- **Results live on the device.** The log is in `localStorage` and moves by Copy or Download. Remote, unattended testing needs a collection endpoint, which is out of scope for Phase 0.
- The business-plan generator scripts (`build_plan.py`, `build_all.py`) are not in this repo; the PDFs they produced are in [`docs/business-plan/`](docs/business-plan).
